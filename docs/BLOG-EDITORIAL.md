# Редакция блогов Praxen AI

Как ведём блоги praxenai.com и praxenai.ge: кто что делает, через какие шаги проходит статья и по каким правилам главред принимает текст. Порядок перенесён из блога Сальдо (`docs/seo/SEPTEMBER_CONTENT_CALENDAR_2026.md` и `docs/seo/ANTI_AI_STYLE.md` в репозитории saldio) и подогнан под два сайта.

## Скиллы (решение владельца 9 октября)

Работаем по пяти скиллам из подборки https://ofis-ai.ru/learn/claude-skills-marketing и по их правилам; остальные скиллы — только вспомогательные.

| Скилл | Где применяем |
|---|---|
| `brand-voice` | Профиль голоса (VOICE PROFILE) для .com и для .ge, собранный из реальных текстов сайта; копирайтер пишет по нему, главред сверяет. Его запреты (hard bans) обязательны |
| `seo` | Тема и запрос статьи: один URL — один интент, карта запросов, поиск каннибализации («объединить или развести»), title 50–60 знаков, description 120–160, перелинковка с понятными анкорами |
| `humanizer` | Финальный проход главреда по каждому тексту: 26 признаков текста от ИИ, сильнейшие (§1–§5) правим с одного появления |
| `content-engine` | Посты в соцсети из статей и страниц: одна мысль на пост, формат под площадку, без дублей текста между площадками |
| `marketing-campaign` | Кампании и запуски (например, LinkedIn для .com): позиционирование и угол до текстов, контент-календарь, проверка обещаний |

Порядок из подборки: `marketing-campaign` (стратегия) → `content-engine` (пачка материалов) → `brand-voice` (тон) → `seo` (тексты блога и сайта) → `humanizer` (последний проход). Для блога минимум — `brand-voice` + `seo` + `humanizer`; для соцсетей — `brand-voice` + `humanizer`, для запусков добавляем `marketing-campaign` и `content-engine`.

Как правила `humanizer` ложатся на наши языки: в русском тире остаётся там, где его требует грамматика (между подлежащим и сказуемым, на месте пропущенного слова), остальные тире заменяем (§8); кавычки — «ёлочки» в русском, в английском как на сайте (§21 сам по себе не повод для правки); пункты списков «Метка: текст» сайт показывает с жирной меткой — метку оставляем, только если она несёт информацию (§19).

| Роль | Кто | Что делает | Скиллы |
|---|---|---|---|
| Владелец | владелец | Даёт «да» на тему и план, потом на публикацию | — |
| SEO-редактор | агент `praxen-seo-editor` | Подбирает тему по спросу, проверяет, что в блоге нет статьи под тот же запрос, пишет бриф и карту ссылок | `seo`; вспомогательные: `seo-cluster` (подсчёт общих адресов в выдаче), `seo-dataforseo`, `yandex-wordstat` |

## Путь статьи

1. **Тема.** SEO-редактор берёт запрос из `docs/seo-data/` или нового замера (DataForSEO, Вордстат). Проверяет выдачу по главному запросу и по соседним статьям блога: если выдача совпадает на 7 из 10 адресов и больше, это одна статья. Тема занята другой статьёй блога — новую не пишем, а дополняем старую.
2. **Бриф.** Главный запрос, вопрос читателя, коммерческая страница, которую статья раскрывает, тезисы, которые уже есть в других статьях (их даём ссылкой), 3 ссылки внутрь сайта.
3. **«Да» владельца на тему и план.** Без него статью не пишем.
4. **Текст.** Копирайтер пишет по брифу и скиллу `praxen-blog`.
5. **Главред.** Проверка по чек-листу ниже. «На доработку» — правки копирайтеру, пока не будет «принято».
6. **Грузинская версия** (.ge) — вычитка командой владельца.
7. **Проверки.** `npx tsx scripts/qa/blog-check.ts`, `npx tsc --noEmit -p .`, `npx eslint components lib app`, сборка, скриншоты на 1440 и 390.
8. **«Да» владельца на публикацию.**
9. **Выкладка.** Пуш в `main`, `node scripts/qa/live-check.mjs`, IndexNow.

Правки опубликованных статей идут тем же путём, с шага 2.

## Уникальность

- **Статья может раскрывать коммерческую страницу** (услугу, отрасль, отдел): отвечает на вопрос подробнее и ссылается на страницу. Текст страницы она не копирует.
- **Внутри блога повторов нет.** Один запрос — одна статья. Один тезис живёт в одной статье-владельце, другие ссылаются на неё и не пересказывают.
- **Общие оговорки** (токены оплачиваются провайдерам, данные остаются на аккаунтах клиента, аудит бесплатный, цифры условные) — не в каждой статье. Полностью — на странице цен и в FAQ; в статье — одной фразой и только там, где без неё читатель ошибётся.
- **Расчёты и примеры у каждой статьи свои.** Одна формула («при стоимости часа 12 ₾ это около … ₾ в месяц») не кочует по статьям.
- **Структура под вопрос статьи.** Не одна схема на все статьи («короткий ответ → пример с расчётом → карточки цен → токены → аудит»); раздел «Сколько стоит» — там, где читатель пришёл за ценой.
- **Между сайтами темы разные.** .com и .ge — разные компании (CLAUDE.md, правило 3).

## Чек-лист главреда

Вердикт по каждой статье: «принято» или «на доработку», замечания по важности, у каждого «было → стало».

1. **Голос.** Спокойно, конкретно, по-деловому; короткие предложения; цифры вместо прилагательных. Без хайпа («революционный», «магия»), без «нейросеть сделает всё». .com — британский английский, «for businesses», Грузия не упоминается.
2. **Ясность.** Первый экран — суть и первый полезный факт. Без вступления-оглавления («Ниже разберём…») и одинаковых заключительных разделов.
3. **Грамотность.** Естественный русский и английский, без кальки.
4. **Правдивость.** Нет выдуманных клиентов, отзывов, статистики. Цифры — с источником или с пометкой, что это пример. Законы и даты — только если уверены. Цены — как на сайте.
5. **Уникальность.** По правилам выше: нет пересказа других статей блога, общие оговорки не размножены, расчёт свой.
6. **«ИИ-шность» — по `humanizer`** (все 26 признаков, номер признака указываем в замечании). Первыми убираем:
   - антитеза «не X, а Y» / "not X but Y" и её мягкие формы («вместо», "instead of", "rather than") — цель 0, максимум 1 на статью;
   - фразы, которые кочуют между статьями;
   - одинаковый каркас начала и конца;
   - один и тот же рефрен во всех статьях («люди решают, ИИ готовит черновик» — один раз и своими словами);
   - афоризмы, драматизация, пустые усилители, хедж-слова («как правило», «обычно») без нужды.
   Ещё: ломать ритм (абзацы разной длины), списки — столько пунктов, сколько есть на самом деле, без подгонки под тройку.
7. **SEO — по `seo`.** Один URL — один интент; главный запрос в начале title и в первом абзаце; title и description по длине; 3 ссылки внутрь сайта с понятными анкорами, одна — на коммерческую страницу, которую статья раскрывает.
8. **Голос — по `brand-voice`.** Текст совпадает с профилем голоса сайта; запреты скилла (фальшивые крючки, «not X, just Y», «no fluff», интонация «лидера мнений» из LinkedIn, вопросы-приманки, «Excited to share», пустая история основателя) — ноль.

«Принято» — когда по пунктам 4–6 замечаний нет, а по остальным остались только мелочи.
